## 장별 설명 범위

### 1장: 과제와 해결할 문제

첫 문장은 “과제 1로, 기존 운영 진단 에이전트에 자연어 조건부 워크플로를 추가했습니다” 정도로 시작한다. 상세 배경·목차·설치 환경은 말하지 않고 조건 지시의 실행 정확성을 목표로 제시한다.

### 2장: 기능 소개

보고서에는 최초 기획의 개선 2개·추가 5개를 유지한다. PPT에서는 모든 문장을 읽지 않고 전체 사용 흐름과 미리보기 화면을 설명한다. 실행 사실 출력·요약 근거 연결·실패 시 사실 제공·비동기 정체 보완은 구현 중 품질 보완으로 분리한다.

사용 캡처: 보고서 그림 1. 저장·재사용 화면인 그림 2는 부록 B로 옮겨도 된다.

### 3장: 결과

비교 질문은 다음 하나를 중심으로 사용한다.

```text
web-01 CPU가 80% 이상이면 CPU 런북, 아니면 메모리 런북을 확인해라.
```

일반 진단의 실제 응답과 워크플로의 최종 실행 화면을 나란히 배치한다. 사용자 수정본의 일반 진단은 CPU 41.9%로 조건을 맞게 해석했고, 메모리 런북을 확인해야 한다고 안내했다. 답변만으로 실제 런북 조회 여부를 확정하지 않는다. 워크플로는 CPU 40.5%로 거짓 분기를 선택해 메모리 런북을 실제로 읽고 CPU 런북을 건너뛴 기록을 보여준다. 모니터링 1회·런북 1회는 실행 기록의 완료 횟수다. 모의 값은 호출마다 달라질 수 있다. 현재 관측값·조건·런북 횟수·문서 제목을 읽을 수 있게 필요한 영역을 확대한다.

healthy일 때 런북 0회인 사례와 CPU가 높은 참 분기는 작은 결과 표로 보완하거나 부록으로 이동한다. 최종 화면에 사용한 질문·수치·실행 ID가 서로 같은 실행인지 확인한다.

사용 캡처: 보고서 그림 4·5. 전체 최종 실행 화면이 더 잘 보이면 그림 6을 활용하고 비교 질문도 그 화면과 맞춘다.

### 4장: 자연어 생성과 Agent Graph

설명할 파일: [compiler.py](../agent/workflow/compiler.py), [graph.py](../agent/workflow/graph.py)

상단에는 `prepare → execute → write → validate_report → finalize`의 고정 5노드와 요약 재작성 연결을 간결하게 표시한다. LangGraph 구조는 고정이며 사용자별 if/else는 `execute` 안의 실행기가 처리한다. 전체 노드 등록 코드를 읽기보다 다음 생성 코드 7줄을 중심으로 설명한다. 현재 PPT는 동일 코드를 줄바꿈 조정해 표시한다. 도식은 정상 경로·요약 재작성을 보여주며, 오류 발생 시 `finalize`로 종료하는 연결은 생략한 그림이다.

```python
response = await llm.compile_workflow(
    query,
    catalog.to_dict(),
    workflow_response_schema(),
    errors=[issue.model_dump(mode="json") for issue in last_errors] or None,
    previous_response=previous_response,
)
```

`compile_workflow()`의 실제 발췌다. 자연어·등록 자원·응답 스키마를 함께 전달하고, 검증 실패 시 오류와 이전 응답을 전달해 한 번만 수정 생성한다. 생성 단계에서는 MCP 도메인 조회를 실행하지 않는다. 미지원 거절·통신 실패·시간 제한은 별도로 종료한다.

그래프와 실행기의 연결은 `build_workflow_graph()`의 다음 한 줄로 보여준다.

```python
graph.add_node("execute", partial(_execute, mcp=mcp, catalog=catalog))
```

대본 순서에 따라 먼저 생성 입력·구조화 계약·수정 생성을 설명하고, 고정 그래프와 실행 노드 연결로 마무리한다. 코드의 모든 줄을 읽지 않고 합계 60초로 연습한다.

### 5장: 실행 전 워크플로 검증

설명할 파일: [models.py](../agent/workflow/models.py), [validator.py](../agent/workflow/validator.py), [intent.py](../agent/workflow/intent.py)

- `IfStep`은 조건과 `then_steps`·`else_steps`를 명시한다. 분기에는 조회 단계만 허용한다.
- Pydantic은 타입·허용 필드·노드 구조와 미선택 분기를 포함한 전체 6노드 상한을 검사한다.
- 정적 검증기는 시스템·런북 등록 여부, ID 중복, 선행 최상위 모니터링 참조를 검사한다.
- 원문 제약 검사는 지원하는 표현 범위에서 순서·대상·비교 경계·분기의 임의 변경을 확인한다. 모든 자연어의 의미를 완전히 판정하는 검사로 설명하지 않는다.

화면에는 `IfStep`의 짧은 구조와 `_semantic_issues()`의 선행 참조 검사 부분을 나란히 제시한다. 설명의 핵심은 **“JSON 형식만 맞는다고 실행하지 않고, 실제로 실행 가능한 참조와 사용자 제약까지 검사한다”**이다. 순환 참조는 선행 최상위 모니터링만 참조하도록 제한하는 구조로 방지한다.

### 6장: 조건 판단과 MCP 조회

설명할 파일: [executor.py](../agent/workflow/executor.py)

- `evaluate_condition()`은 검증한 스냅샷의 실제값·연산자·기준값으로 조건을 계산한다.
- `run_condition()`은 미선택 분기를 `skipped`로 기록하고 선택 분기만 실행한다.
- 모니터링은 `call_tool()`, 런북은 템플릿 탐색·허용값 검사 후 `read_resource()`로 읽는다.
- 조회·응답 검증 실패는 오류로 처리하며, 조건의 거짓으로 바꾸어 다른 분기를 실행하지 않는다.

선택 분기를 실행하는 코드를 가장 크게, 두 MCP 호출 부분을 작은 별도 박스로 보여준다. 실제 조회 결과로 분기를 결정하는 점을 3장의 시연과 연결한다. 보고 사실 출력·문단 참조 검사는 부록 B의 보완 사항으로 설명한다.

### 7장: 회고 자료

5분 발표에서는 생략하고 제출·질의응답 자료로 유지한다. 문장 예시:

> 모델의 자연스러운 답변과 실제 실행 정확성을 따로 검증해야 한다는 점을 배웠습니다. 다음에는 런북 요약의 전제조건 보존과 새 문항의 일반화 성능을 보완하겠습니다.

### 부록 B: 기술·검증 근거

실제 사용한 LangGraph, LLM 구조화 출력·Pydantic, MCP, 의존성 주입·모듈화, SQLite·POST SSE, LangSmith, 자동화 테스트를 적용 내용과 함께 정리한다. 기술표는 현재 PPT의 9장 부록에 있으므로, 5분 발표에서는 4장의 LangGraph·구조화 출력·의존성 주입, 5장의 Pydantic, 6장의 MCP를 코드와 함께 언급한다. 실제 촬영한 테스트 결과 또는 저장·재사용 화면 중 설명에 필요한 하나를 크게 넣는다. LangSmith는 실제 수집한 trace가 있을 때만 화면을 추가한다. **2026-10-22 재검증은 Python 381개·Node 46개 통과**이며 전체 프로젝트 검증 수다. 신규 단위 테스트만의 개수가 아니다.

보고 정확성 보완은 6장 대본에서 짧게 언급하고, 부록 B 하단 문구와 수동 입력 가이드에서 보충한다. 관측값·조건·조회 횟수는 코드가 작성하고, 모델은 실제 읽은 런북의 문단만 요약한다. 문서·문단 ID와 일부 수치를 검사하고 원문을 함께 표시하며, 요약 실패 시에도 확인된 조회 사실을 제공한다. 다만 전제조건 누락·의미 변경까지 모두 판정하지는 못한다. 이는 핵심 조건부 실행을 뒷받침하는 품질 보완이며 본문 코드 설명의 중심과 구분한다.

## 보고서와 PPT의 정보량

보고서는 상세 구현·7개 주요 task·검증 조건·실패 사례·한계·출처를 유지한다. PPT 본문은 각 장에 설명할 주장 하나와 그 근거 화면·코드를 배치한다. 표지·목차·기술 이름 나열만을 위한 별도 슬라이드는 만들지 않는다. 현재 2·3장에는 실제 화면이 들어갔고 **8·9장의 캡처 4·5가 남아 있다.** 1장에는 `G094·임해안`이 입력됐으며 2~9장에는 식별 정보가 보이지 않는다. [수동 입력 안내](presentation/assignment1_ppt_fill_guide.md)에 따라 부록 캡처·페이지별 식별 정보를 넣고, 6장 하단에 남은 “이번” 텍스트를 삭제한 뒤 제출한다.

각 코드 박스는 약 5~8줄, 설명 포인트는 2~3개로 제한한다. 한 메서드 전체를 붙이지 않고 생성 계약·참조 검사·선택 분기 실행을 드러내는 부분을 발췌한다. 전체 웹 화면을 작게 붙여 글자가 읽히지 않으면 조건·조회 횟수·선택 런북 영역을 확대한다. 원본 전체 화면은 부록에 둘 수 있다.
