# 조건부 워크플로 화면 사용법

<!-- [추가] 현재 코드 대조 시점과 실행 결과의 저장 범위를 명시한다. -->
코드 대조일: 2026-10-22. 저장 목록은 절차 정의를 다시 여는 기능이며 지난 실행 결과 목록은 아니다.

## 실행과 사용 순서

프로젝트 루트의 첫 터미널에서 백엔드를 실행한다.

```bash
LLM_BACKEND=fake ./.venv/bin/python3 server.py
```

다른 터미널에서 웹 서버를 실행한다.

```bash
./.venv/bin/python3 web_demo_server.py
```

`http://localhost:8600`을 열고 **조건부 워크플로** 탭을 선택한다. Vue는 기존과 같은 CDN 글로벌 빌드를 사용하므로 별도 npm 설치·빌드가 없다.

1. 예시를 선택하거나 자연어 요청을 입력하고 절차를 생성한다. fake에서는 화면의 고정 예시를 사용한다.
2. 미리보기에서 대상 시스템, 조회 순서, 조건식, 양쪽 분기를 확인한다. 생성만으로 MCP 조회를 실행하지 않는다.
3. 이름을 지정해 저장한다. 저장하지 않은 초안도 실행할 수 있다.
4. 실행 버튼을 누른다. 화면의 정의 해시를 POST body로 보내며, 서버는 저장된 정의와 비교한 뒤 실행한다.
5. 실제 조건값, 선택한 분기, 건너뛴 단계, 조회 자료, 최종 보고를 확인한다.
6. 저장 목록에서 절차를 다시 불러와 실행한다. 정의를 재생성하지 않고 새 모니터링 값으로 조건을 계산한다.

입력은 최대 2,000자이며 전체 노드 수는 실행하지 않는 분기와 조건 노드를 포함해 최대 6개다. 빈 분기는 그 분기에 추가 조회가 없다는 뜻이며, 뒤에 최상위 단계가 있다면 계속 실행한다. 지원 시스템·런북·조건 필드는 화면의 카탈로그에서 확인한다.

일반 진단 탭의 기존 대화와 워크플로 상태는 탭 전환 시 유지된다. 백엔드는 `LLM_BACKEND`로 정한다. Ollama의 워크플로 생성은 기본적으로 보고 모델과 같은 모델명(기본 `qwen3:8b`)을 선택하되 별도 생성 어댑터를 사용하며, `OLLAMA_WORKFLOW_MODEL`로 지정할 수 있다. `/health`의 `workflow_llm`에서 확인한다. [OpenAI 평가 결과](workflow_openai_regression_results.md)와 Ollama 두 요청의 생성·분기 점검을 별도로 기록했다.

## 결과와 오류 읽기

- **초안과 확정 보고:** 작성 중에는 요약·검증 진행 상태를 표시하며, 미검증 모델 JSON을 실시간으로 보내지 않는다. 검증 후 합성 보고를 한 번 전달하고 최종 성공 이벤트의 결과를 확정 보고로 표시한다. 실패 결과에 마지막 `draft`가 있으면 미확정 초안으로 보여준다. 런북 0건이면 **보고 모델** 호출 없이 사실 보고를 확정하며, 절차 생성의 모델 호출과는 별개다. 형식·참조 검사를 통과해도 요약 의미 전체의 정확성을 보장하지는 않는다.
- **조건과 조회 자료:** 조건의 실제 값·연산자·기준값과 선택 분기를 표시한다. 실행하지 않은 분기는 건너뜀으로 표시하며, 모니터링 값과 런북 원문은 별도로 확인한다.
- **사용량:** 공급자가 토큰 수를 제공하지 않으면 미제공으로 표시한다. fake의 수치는 추정치다. 생성과 보고 사용량을 실제 API 청구 금액으로 환산하지 않는다.
- **HTTP 오류:** 생성 실패 응답에 검증 오류가 있으면 code·path·message를 펼쳐진 목록으로 표시한다. 최종 목록이 없으면 마지막 생성 시도의 오류를 사용한다. 사전 거절처럼 검증 오류가 없는 경우에는 상단 코드·설명과 제공된 원본 상세 정보를 확인한다. 409 충돌이면 저장된 절차를 다시 불러와 검토한 뒤 실행한다.
- **연결 끊김:** 종료 결과를 받지 못하면 완료 확인 불가로 표시한다. 최종 결과를 이미 받았다면 그 결과를 유지하고 전송 종료 확인 문제를 별도로 알린다. 자동 재실행하지 않는다.

브라우저 새로고침 후에는 저장 목록에서 정의를 다시 열 수 있다. 실행 이벤트·결과의 영구 이력, 자동 재접속 복원, 취소·체크포인트 재개 기능은 없다.

화면은 Vue 텍스트 보간으로 서버 텍스트를 표시한다. 워크플로 실행에는 자동 재접속하는 `EventSource`를 사용하지 않고 `fetch` POST를 사용한다. 프록시는 실행 전 발생한 404·409 등을 일반 HTTP 오류로 전달한 뒤, 성공한 스트림의 바이트를 중계한다.

서버는 요청 내부에서 이벤트 전달 버퍼를 최대 1개로 유지하고, 요청 종료 시 생산 Task를 취소한 뒤 종료를 기다린다. 조회·보고 응답을 기다리는 중이거나 이벤트를 보내는 중에 연결이 끊겨도 응답 본문 제너레이터와 upstream 연결 정리를 완료한다. 원격 모델의 계산·과금까지 즉시 중단된다는 보장은 없다.

## 검증 명령

<!-- [추가] 화면·프록시 연결 및 종료 정리 보완 후 실행한 전체 회귀 결과다. -->
로컬 모델 분리·검증 오류 표시·일반 진단 응답 정체·보고 정확성 보완 후 전체 Python **381개**, Node **46개**가 통과했으며, 2026-10-22 오프라인 회귀에서도 같은 결과를 재확인했다. Node는 SSE 30개·setup 16개다. 보고 모델이 실패해도 조회 성공 시 `facts_report`를 “확인된 조회 결과”로 별도 표시한다. [보고 정확성 보완](workflow_report_accuracy.md)을 참고한다. Python에는 프록시 22개와 조회·보고·전송 중 ASGI 연결 종료 회귀, 별도 평가 도구·의도 검사·모델 선택·동시 API 응답 테스트가 포함된다. [평가 안내](workflow_evaluation.md)와 일반 진단 응답 정체 수정을 참고한다.

```bash
LANGSMITH_TRACING=false LANGCHAIN_TRACING_V2=false ./.venv/bin/python3 -B -m unittest discover -s tests -v
```

Node 테스트는 내장 `node:test`, `fetch`, `ReadableStream`을 사용하며 Node 22 이상을 권장한다. 2026-10-22 확인한 개발 환경은 Node **v26.7.0**이다. setup 테스트는 Vue 대역으로 제어 흐름을 검사하며 실제 DOM 렌더 검사를 대체하지 않는다. 브라우저에서는 임시 DB·fake 모델·실제 로컬 MCP로 생성·저장·실행·새로고침 후 다시 불러오기·새 값으로 재실행과 400px 화면 배치를 확인했다. 기존 일반 채팅·인시던트 진단도 확인했다. API 요청 예시·환경변수는 [워크플로 API 사용법](workflow_api.md), 전체 범위와 후속 평가는 [구현 계획](workflow_implementation_plan.md)을 참고한다.
