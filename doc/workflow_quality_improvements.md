## 1. 요청 전체의 지원 범위 검사

`query_issues()`는 모델 호출 전에 현재 카탈로그와 명시적인 표현을 검사한다. 미등록 식별자, 지원하지 않는 운영 변경·반복·병렬·중첩·로그 조회, 기준값이나 참조 대상이 불명확한 조건 등을 확인한다. 예를 들어 “CPU가 높으면 적당한 런북”에서 임의로 `>= 80`과 CPU 런북을 채우지 않도록 한다.

명백한 미지원 요청은 `UNSUPPORTED_REQUEST`로 종료한다. 조회와 재시작을 함께 요청했어도 재시작을 빼고 조회만 하는 부분 절차를 만들지 않는다. 런북에 있는 재시작 권고를 **읽는 요청**과 실제로 재시작하라는 요청은 구분한다. 이 단계에서 거절되면 생성 모델 호출과 도메인 조회를 수행하지 않는다.

## 2. 생성 절차의 의도 제약 대조

JSON·스키마·카탈로그·참조의 정적 검증을 통과한 후보에 `definition_issues()`를 적용한다. 해석 가능한 범위에서 명시된 시스템·런북의 종류와 순서, 추가 조회, 조건 수, 지표·연산자·기준값, 참조 시스템, 참·거짓 분기의 조회 범위를 대조한다. 순차 요청에 임의 `if`를 넣거나 두 번째 시스템의 조건을 첫 번째 시스템에 연결하면 `INTENT_MISMATCH` 오류를 모델에 되돌려 보낸다.

생성은 **최초 1회와 수정 1회를 합쳐 최대 2회**다. 형식·의도 오류와 이전 후보를 전달해 수정하고, 계속 실패하면 승인하지 않는다. 공급자의 거절·통신 오류·명시적인 미지원 응답은 수정 생성으로 반복하지 않는다. 생성 중에는 MCP 조회를 실행하지 않는다.

<!-- [추가] v2 회귀에서 발견한 동등 조건 오탐과 반복 관측 참조의 한계를 보완한다. -->
비교 연산자를 정확한 반대로 바꾸면서 양쪽 분기를 전체 교환한 후보는 실행 의미가 같다. v3는 검사할 사본에서만 이를 원문 방향으로 정규화해 승인한다. 원본 AST·ID·저장 해시는 변경하지 않는다. 연산자만 반전하거나 분기 일부만 교환한 경우에는 계속 거절한다. 같은 시스템을 여러 번 관측한 뒤 조건에서 특정 관측을 참조하는 요청은 이 파서가 회차를 보장하지 못하므로 명확화를 요구한다. 단일 관측 후 조건에 시스템 이름을 다시 적는 경우는 허용한다.

생성 프롬프트의 대조 예시는 평가 문항의 정답 대신 가상의 `system-a`, `system-b`, `runbook-a` 등을 사용한다. 순차 조회에는 조건을 넣지 않는 경우, 런북만 순서대로 읽는 경우, 두 번째 시스템을 조건에 참조하는 경우, 운영 변경 요청 전체를 거절하는 경우를 구분한다. 공통 후속 단계는 원문이 명시할 때만 분기 밖에 추가한다. 수정 시 원문 밖 노드를 삭제해야 하며 다른 등록 자원으로 바꿔 유지하지 못하도록 명시했다. 실제 자원은 항상 해당 요청의 카탈로그에서 선택해야 한다.

## 3. 실제 조회에 근거한 보고 작성

<!-- [추가] 자유 서술 사실 작성에서 코드 출력·문단 참조 요약으로 바뀐 현재 경로다. -->
관측값·조건식·분기·조회 횟수·건너뜀은 `report_content.py`가 완료 trace와 자료로 직접 출력한다. 런북이 없으면 보고 모델을 호출하지 않는다. 런북을 읽은 경우 모델에는 실제 문단과 ID만 전달하고, 문서·문단 참조 JSON을 검증한 뒤 요약과 서버가 가져온 원문을 함께 표시한다.

기존 `validate_grounded_report()`의 한정된 허위 조치 완료 검사는 모델 요약에 적용한다. 각 조회 문서가 빠짐없이 한 번씩 요약됐는지, 실제 문서·문단 ID를 참조하는지, 선택한 문단에 없는 수치를 추가했는지 검사한다. 이어 코드가 합성한 보고의 길이·번호 순서·응답 완료 여부를 검사한다. 최초 작성을 포함해 최대 세 번 시도하며, 검증 오류로 재시도할 때는 MCP 조회를 반복하지 않고 요약만 다시 작성한다. 모델 거절·연동 오류·시간 초과는 해당 오류로 종료한다. 끝까지 실패하면 확정 보고는 비우고, 조회 성공 시 코드가 만든 `facts_report`는 별도로 제공한다. 미검증 모델 JSON은 답변 스트림으로 보내지 않는다.

과거 v3에는 읽기 전용 계약과 중립 ID를 모델에 전달했다. 현재는 모니터링·trace 자체를 요약 입력에서 제외했다. 구체적 코드·예시·검증 범위는 [보고 정확성 보완](workflow_report_accuracy.md)을 참고한다.

## 제약과 결과 해석

- 의도 검사는 명시한 자원·비교·조회 표현을 읽는 보수적인 규칙이며 전체 자연어 파서나 의미 동치 증명기가 아니다. 다른 표현을 잘못 거절하거나 범위 밖 오류를 놓칠 수 있다.
- “같은 시스템을 두 번 조회”처럼 횟수만 적는 표현은 각 조회 단계에 이름을 따로 적도록 요청한다. 기존 저장 정의를 자동 재작성하지 않으며, 새 생성 요청에 의도 검사를 적용한다.
- 지원한 6개 비교 연산자의 정확한 반전과 양분기 전체 교환은 허용한다. 이 외의 논리식 재작성까지 증명하는 범용 동치 판정기는 아니다. v2의 원문 연산자 강제 정책에서 발생한 정상 후보 거절도 [회귀 결과](workflow_openai_regression_results.md)에 보존했다.
- 보고 검사는 명시된 표현의 모순을 차단하는 경계다. 우회적인 동의어, 인용의 진실성, 일반 수치·임계값·원인·인과 관계까지 전수 검증하지 않는다. `report_valid=true`는 전체 사실성을 보장하지 않는다.
- 같은 24개 문항으로 보완 전후를 다시 측정하면 **회귀 평가**다. 기존 dev와 holdout의 실패를 이미 확인하고 수정했으므로 재측정을 독립적인 holdout 성능으로 발표할 수 없다. 일반화 성능은 별도의 새 문항으로 확인해야 한다.
