# OpenAI 평가 기록 기반 비용 추정

계산일·단가 확인일: **2026-10-22**. 토큰 원기록은 **2026-10-21**의 평가 자료다. 새 모델 API 호출 없이 보관한 `results.json`의 공급자 실측 입력·출력 토큰을 계산했다.

**초기 v1의 지원 18문항·34시나리오에서는 일반 진단 $0.07827075, 워크플로 $0.21613080으로 추정됐다.** 워크플로 비용이 약 **2.76배** 높았다. 이 결과는 캐시 할인 전 표준 토큰 사용료 추정이며, 실제 청구액이나 최신 버전의 재측정 결과가 아니다.

## 1. 적용한 단가와 계산 방식

일반 텍스트 요청의 100만 토큰당 USD 단가를 사용했다. Batch 할인을 적용하지 않았다.

| 모델 | 입력 | 출력 | 공식 근거 |
|---|---:|---:|---|
| `gpt-4o-mini` | $0.15 | $0.60 | [OpenAI 모델 문서](https://developers.openai.com/api/docs/models/gpt-4o-mini) |
| `gpt-4o` | $2.50 | $10.00 | [OpenAI 모델 문서](https://developers.openai.com/api/docs/models/gpt-4o) |

```text
모델별 비용 = (입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가) / 1,000,000
전체 비용 = 모델별 비용의 합
```

원기록에는 캐시된 입력 토큰의 상세 수가 남아 있지 않다. 캐시 토큰을 0으로 관측했다고 가정하지 않고, 모든 입력에 일반 단가를 적용한 **할인 전 추정치**로 표시했다. 캐시 할인, 계정 크레딧·세금·환율·계약 요율, LangSmith와 서버 운영비는 반영하지 않았다.

## 2. 같은 지원 시나리오의 전후 비교

`openai-dev/results.json`과 `openai-holdout/results.json`에서 `supported=true`인 문항의 호출만 집계했다. 미지원 6문항의 처리 비용은 이 표에서 제외했다. 따라서 기존 문서의 미지원 문항 포함 전체 호출 수 118회·60회와 이 표의 호출 수는 다르다.

| 지표 | 기존 일반 진단 | 초기 워크플로(v1) |
|---|---:|---:|
| 지원 문항 / 실행 시나리오 | 18 / 34 | 18 / 34 |
| 모델 호출 수 | 101회 | 51회 |
| 입력 토큰 | 26,820 | 86,617 |
| 출력 토큰 | 6,681 | 11,808 |
| 총 토큰 | 33,501 | 98,425 |
| 할인 전 추정 비용 | **$0.07827075** | **$0.21613080** |
| 시나리오당 단순 평균 | 약 $0.002302 | 약 $0.006357 |

워크플로는 문항별 생성 비용을 한 번씩 집계하고 이후 관측 시나리오에서는 저장된 정의를 재사용한 조건이다. 각 시나리오에서 절차를 새로 생성하는 사용 조건과 다르다. 모델이 실제로 다시 호출된 수정·보고 시도는 최상위 호출 기록에 포함된 만큼 집계했다.

원문의 요청을 충실히 수행했는지와 무관하게 당시 발생한 호출을 모두 포함했다. 생성 실패·거절로 실행하지 않은 시나리오, 일반 진단의 다른 라우팅, 잘못된 경로도 남아 있으므로 동일한 품질의 성공 작업당 비용 비교는 아니다.

### 단계별 비용

| 방식·단계 | 모델 | 호출 수 | 입력 토큰 | 출력 토큰 | 추정 비용 |
|---|---|---:|---:|---:|---:|
| 일반 진단의 fast 모델 호출 | `gpt-4o-mini` | 69 | 16,487 | 1,792 | $0.00354825 |
| 일반 진단의 quality 모델 호출 | `gpt-4o` | 32 | 10,333 | 4,889 | $0.07472250 |
| 워크플로 절차 생성 | `gpt-4o-mini` | 18 | 42,970 | 1,863 | $0.00756330 |
| 워크플로 실행 후 보고 | `gpt-4o` | 33 | 43,647 | 9,945 | $0.20856750 |

이 기록에서는 **모델 호출 수가 줄어도 비용이 줄지 않았다.** 워크플로의 생성에는 스키마·카탈로그가 들어가고 당시 자유 서술 보고에는 실행 자료·trace가 포함됐다. 보고의 입력·출력 토큰도 일반 진단보다 많았다. 초기 워크플로 추정 비용 중 약 96.5%는 `gpt-4o` 보고 단계였다. MCP 조회 횟수 감소를 OpenAI 비용 절감으로 해석하지 않는다.

현재 코드는 실행 사실을 코드로 작성하고 모델에는 런북 문단 요약을 요청하도록 계약이 바뀌었다. 현재 버전의 보고 비용과 절차 재사용에 따른 비용 변화는 새로 측정해야 한다.

## 3. 보관된 평가 5개 파일의 합계

다음은 지원·미지원 문항과 각 회차의 실제 호출을 모두 포함한다. 2절의 지원 시나리오 전후 비교와 집계 범위가 다르다.

| 기록 | 모델 호출 | 총 토큰 | 할인 전 추정 비용 |
|---|---:|---:|---:|
| 초기 v1 dev | 87 | 77,533 | $0.15135270 |
| 초기 v1 holdout | 91 | 80,534 | $0.17161390 |
| 별도 소규모 연동 확인 | 4 | 7,663 | $0.02037540 |
| v2 회귀 평가 | 50 | 126,190 | $0.23844375 |
| v3 회귀 평가 | 52 | 135,805 | $0.27728090 |
| **합계** | **284** | **427,725** | **$0.85906665** |

각 회차의 문항·완료 시나리오 수가 달라 v2와 v3의 비용 합계만으로 효율을 비교하지 않는다. 이 합계에는 최근 브라우저에서 실행한 일반 진단·워크플로, 다른 실험이나 기록이 없는 요청은 포함하지 않았다. 프로젝트 전체 또는 계정 전체의 청구액을 뜻하지 않는다.

## 4. 재현·검증

[오프라인 계산기](../eval/calculate_openai_costs.py)는 Python 표준 라이브러리만 사용한다. `.env`, 사용자 DB, OpenAI API, LangSmith API에 접근하지 않는다.

```bash
python3 -B eval/calculate_openai_costs.py
```

- 입력: `eval/results/{openai-dev,openai-holdout,openai-smoke-run,openai-v2-regression,openai-v3-regression}/results.json`
- 출력: `eval/results/openai-cost-analysis/summary.json`
- 입력 원자료와 JSON 출력은 기존 `eval/results/` 제외 규칙에 따라 Git에서 제외된다. 새로 복제한 저장소에서는 보관 원자료를 별도로 준비해야 한다.
- 최상위 `model_calls`만 집계해 `cases`·`scenarios`에 복사된 사용량을 중복 합산하지 않는다.
- 284개 호출 모두 입력·출력·총 토큰이 공급자 실측이며, 입력+출력과 총 토큰의 일치 및 각 원본 파일의 합계를 대조했다.
- 알 수 없는 모델·누락 토큰·비실측 사용량·불일치 토큰·오류 호출은 비용 0으로 대체하지 않고 계산을 중단한다.
- 소수 금액은 `Decimal`로 합산하고 원자료 파일의 SHA256을 출력에 남긴다. 평가 원본은 수정하지 않는다.

기존 앱의 `cost_usd`는 총 토큰에 가상 혼합 단가를 곱한 실습용 값이다. 이번 계산은 모델별 입력·출력 단가를 적용하므로 그 값과 계산 방식이 다르며, 앱의 비용 표시 로직은 변경하지 않았다.

## 5. 발표에 사용할 설명

> 초기 v1의 동일한 지원 34개 시나리오에서 모델 호출은 101회에서 51회로 줄었지만, 캐시 할인 전 추정 비용은 약 0.078달러에서 0.216달러로 증가했습니다. 구조화 생성과 보고에 쓰인 토큰이 늘었기 때문입니다. 이번 개선의 성과는 조건에 맞는 실행과 실행 경로 확인이며, 비용 절감까지 입증한 것은 아닙니다.
